# Abacus

A browser equation workspace built from the original ABACUS SWF's textures, face-on 3×3 trays and equals mirror. Numbers are physical cards: each occupied cell holds 1, 10 or 100 card faces, so place value is visible as stack depth. Addition carries and borrows card by card, positive and negative cards cancel in zero pairs, multiplication copies cards, and long division deals them into equal groups. In graph mode, a point dragged along a curve shows its coordinates as card stacks, and systems of equations are solved where curves cross. The Machine rebuilds the user's PRIME.swf function machine in LED bulbs: numbers drop down wires into blocks, and multiplication splits into shifts and sums. An advanced module sweeps card strips under a curve to build an integral. A tutor shows worked examples and then deals the learner fresh problems. The original SWF remains available at `reference.html` for comparison.

## Run

Node.js 20+ for the app and unit tests (Node 22+ for the headless-Chrome checks); no package installation.

```sh
npm start                 # http://localhost:5173
npm test                  # unit and property tests
npm run test:visual       # deterministic SVG snapshots
npm run test:visual:machine  # the Machine's SVG snapshots
npm run test:browser      # real pointer/keyboard/tutor/machine checks in headless Chrome
npm run perf              # frame times of heavy animations in headless Chrome
npm run videos            # narrated tutorial videos (see Tutorial videos)
npm run videos:machine    # the ten silent, captioned Machine explainers
npm run build && npm run preview
```

Stop development before previewing on the same port, or set PORT. `dist` is a static deployment with relative URLs and precompressed assets. The browser checks find Chrome automatically (set `CHROME=/path/to/chrome` otherwise) and skip if none is installed.

## Using it

**Entering problems.** Type or use the original-style 3×3 counting pad (hover lights cumulative cells; the folded corner on 9 enters a decimal point). Up arrow, the upper triangle or Enter deploys the input; the Equation dialog takes a whole problem. `×` (or `*`) multiplies and `÷` (or `:`) divides; numbers joined by them stay one **operation term** in a dashed frame until worked out. A slash between numbers is a fraction (`3/4`). `^` (or ², ³) raises a number or a parenthesised sum to a whole power from 2 to 6. Numbers added inside parentheses stay grouped, drawn between parentheses, until worked out. Decimals up to six places and linear algebra in x are supported.

**Dragging.** Cards have weight: the held card follows the pointer on a critically damped spring.
- The equals mirror resists like a membrane. The card's edge stops at the mirror, which bows under the push; push further and the card pops through and flips sign (red ↔ blue). A small step back meets the membrane again rather than flipping back.
- While a lifted card leaves its side lighter, the equals bars tilt into `<` or `>`, as the original SWF did; they level once the card has crossed.
- Like cards on the card's side are outlined; near one the card is attracted, and close enough it snaps on, outlined red for a zero pair (opposite signs cancel) or teal for a combination. Release to combine; hold Shift on release to place it beside instead.
- Elsewhere, the other cards spring apart and a dashed ghost shows where the card will land. The mirror and any merge target stay put, so nothing slides away from the pointer. Releasing without a change springs the card home.
- Tap an operation term (or focus it and press Enter) to work it out. Arrow keys move a focused card across; Shift + arrows rearrange.

**Working out × and ÷.**
- *Multiplication* extends the original's `Multiplication.Duplicator`. The factor with fewer cards becomes a horizontal line of cards; the other is copied once per card. A ten-card copies it one place up, so its cards become ten-stacks, and a tenth-card copies it one place down. The copies are then added into the answer card by card, carrying tens. `23 × 14` shows one copy of 230 and four of 23.
- *Long division* shares the dividend: each place's cards, largest first, are dealt round-robin into equal groups, and leftovers unstack into ten cards of the next place. While the answer terminates, dealing continues into tenths and hundredths (`7 ÷ 4 = 1.75`). Otherwise each leftover card is sliced into equal strips, one per group, giving a mixed number of whole cards plus a sliced card (`7 ÷ 3 = 2⅓`). One group becomes the answer.
- *Dividing by a fraction* first turns the fraction over (`6 ÷ ½` becomes `6 × 2`).
- *Order of operations (PEMDAS).* Working a term out follows the rule: parentheses first (a product inside them before their sums, the sums from the left), then exponents, then × and ÷ from the left. Across the equation, every parenthesis is worked out before any exponent, and every exponent before any × or ÷; then the cards are added. A power standing alone is written out as repeated multiplication (`2³` becomes `2 × 2 × 2`) so the copies can be shown; inside a chain it is worked out in place (`18 ÷ 3²` is `18 ÷ 9`, never `18 ÷ 3 × 3`). Parentheses and exponent steps play as a captioned crossfade (`(5 − 3)² = 2²`, `2² = 2 × 2 = 4`). A minus written outside parentheses stays there in the text, and the cards inside turn red.
- Tapping a fraction divides it out into a decimal (`3/4 → 0.75`) or a mixed number.
- Visual plans cover divisors up to 12, up to 24 copies and dividends up to six digits. Larger or fractional cases use an exact symbolic transition.

**Graph mode** (header: Graph) plots up to three equations in x and y:
- `y =` a polynomial in x up to degree 4, such as `y = x^2 - 2x - 3` or `y = (x+2)(x-1)(x-3)/2`;
- linear equations such as `2x + 3y = 12`;
- vertical lines such as `x = 3`;
- one-variable equations, graphed as both sides (`x^2 = 4` becomes `y = x²` and `y = 4`).

Drag the point along a curve. Its coordinates are laid out in square cards, one grid unit each and drawn like the tray cards, side by side: a column of y cards stands on the x axis up to the point and a row of x cards runs from the y axis out to it. Each lies just outside the point, so the two meet at its corner without overlapping (they slide, rather than jump, as the point crosses an axis), and both lie under the curves. Cards are blue when positive and red when negative, cut exactly at fractions, and every ten are outlined as a group. The point moves on a spring, steps in friendly fractions (arrow keys also step it), and settles into detents at x-intercepts (roots), the y-intercept, turning points and crossings. These are exact where rational and marked ≈ otherwise. Each equation is checked by substituting the point. At a system's crossing every equation holds; parallel and identical lines are explained.

**Intercepts.** Where a curve collides with an axis one coordinate is zero, so one set of cards vanishes. When the point lands there the axis lights up with the zero it stands for, the device gives a firmer haptic bump, and the panel solves the equation with the zero substituted: on the y axis `2(0) + 3y = 12 → 3y = 12 → y = 12 ÷ 3 = 4`, on the x axis `2x + 3(0) = 12 → 2x = 12 → x = 6`. For a parabola or cubic the panel names every root and checks the one the point is on. **From the cards** graphs both sides of the card-space equation; their crossing is its solution. Pan by dragging the background, and zoom with the wheel or a pinch.

**Area (advanced).** Tick *Area*, choose [a, b], a strip width Δx and where each strip takes its height, then **Sweep**. The point moves across and stacks a column of card strips at each step. Every column then slides beside b and becomes whole cards (same area), and red cancels blue. The resulting stack is marked against the exact integral, computed from the antiderivative. **Thinner strips** halves Δx, and the sum approaches the integral.

**Tutor.** Choose a lesson (ten makes a stack, full trays stack again, moving cards, zero pairs, equal groups, x on both sides, fractions, products, multiplying by copying, two-digit lines, decimal copies, long division, remainders as decimals or fractions, dividing by a fraction, carrying, borrowing, six order-of-operations lessons (multiply before adding, × and ÷ from left to right, parentheses first, exponents as repeated multiplication, + and − from left to right, all of PEMDAS; these also add and subtract strictly from the left), and four graph lessons: solve a system by graphing, where a parabola meets zero, intercepts (drag to the y axis and set x = 0, then to the x axis and set y = 0), graph both sides). The tutor plays a worked example step by step, or with Play all, narrating each step, then deals a new problem of the same shape. Every launch deals a fresh worked example for every lesson from a random seed, so the lessons differ each time the app opens (`?examples=written` keeps the written examples, as the browser tests and videos do). Narration names every carry and borrow a combination causes. Hint highlights the card to move and draws a guide arrow; Show me performs the step; feedback says whether a move helped, was a balanced detour, or solved it. Solve and Combine use the same step planner.

**Prime components (Numbers).** Every whole number can also be written by its prime components, in the marble language of the riemann-zeta-visualization games (ported from `MarbleFingerprint.cs` and `MarbleLayout.cs` to `src/numbers/`). A **marble fingerprint** reads left to right along a thin string: a badge marble in the number's own colour (gold always a prime, deep red a prime squared, blue a pronic number k(k + 1), grey any other composite, white 1), then one round gold container per prime factor holding that many marbles in a symmetric spiral (a pair, a triangle, a pentagon; past six, a centre and equal arms). The exponent is in the container itself: more rings round it, each tilted out of the picture into a plane of its own, like the rings of an armillary sphere, near half bright and far half faint. Count all of a container's rings, its own included: 360 = 2³ · 3² · 5 has two tilted rings round the 2 and one round the 3.
- **Numbers** (header) shows one number's fingerprint, opening on the biggest whole number in the equation. Drag right (or Pull apart, the slider, U) and it unpacks: the tilted rings slide out along the string as containers of their own, the first container pours into the volume, and each next prime p sends one marble to each of p spots where a copy of the volume so far blooms; the copies swirl into p arms (360 ends as five arms of 72, 1001 as thirteen arms of 77). Drag left to pack it. ← → step the number, Digits labels the primes and exponents, and the panel names the number's kind and writes it in every base as card trays. To the cards puts it in the equation space. Primes past 2000 are written in their container rather than drawn as marbles; volumes past 40 000 marbles do not unpack. Factoring is exact to 15 digits (Miller–Rabin and Pollard's rho).
- A **long press** on a whole number shows its fingerprint and prime components above its places.
- View ▸ **Prime fingerprints under whole numbers** draws every whole number's fingerprint beneath its cards.

**Machine** (header: Machine) is PRIME's function machine (`public/PRIME.swf`, specified in [docs/prime-reference.md](docs/prime-reference.md)) rebuilt in LED bulbs; the design is [docs/machine-design.md](docs/machine-design.md). Numbers go into the Input pill, ride down wires into blocks hung under the triangle, and come out of the Output pill. A number is a **tower**: one bulb per level, the units bulb in the socket, so place value is height. Blue bulbs are positive, red negative (with a bar across, so colour is never the only cue), dark bulbs are 0.
- **Open** it on PRIME's demo: base 2, a × block under the triangle and `[16,7]` in Input. Press **Enter**. With AUTO on (the default, remembered) the whole run plays: 16 × 7 splits into 16 × 4 + 16 × 3, the multiplicand rises level by level, the partial products ride up and collide, and Output reads `[112]`. With AUTO off each Enter plays one beat, so 16 Enters reach `[112]` without leaving the Input. Enter mid-run finishes the current beat; after the Output, or after any edit, it starts over.
- **Build** a machine by tapping a socket (on the stage, or in Parts) and then a block, or by dragging a block onto a socket; dropping on a taken socket pushes that block into the new one's left socket. Backspace takes a selected block off. The expression field builds the machine from `16*7`, `(5+3)*7`, `45/6`, `45%6`, `12&10`, `~5`, `7<=>9`, `5<<3`, `shr(45,2)`, `min(2,1)`, `sum(5,7)`, `ln(112)`, `measure(3)` or `-(3+4)` (0 − (3 + 4) in a base without a NEG block), and fills Input (brackets optional: `16,7` or `16 7`). `>>` is refused: in the machine a right shift truncates like ÷, so write `shr(−13, 2)`.
- **Bases.** 2 (sign-magnitude arithmetic, and two's-complement logic drawn with a red sign lamp above the top), balanced ternary ±3 (signed natively: NOT is negation, MIN, MAX, SUM and CONS are the gates) and e (loaded on first use: exact towers with dust below level −3, logarithms as heights). Base e greys out what it cannot do, with the reason.
- **Controls.** Enter, → or ↓ step (the Enter rule); ← or ↑ back a beat; A toggles AUTO; Space pauses; `[` and `]` make beats slower or faster (0.25 to 3 s, from the next beat); Home and End restart and finish; R rewinds; T follows the active block, O fits the whole machine; D shows place values and digits; P switches carries between together (PRIME) and one level at a time; B cycles the base; Esc closes the Steps sheet, leaves a field or control, and again the mode. Shortcuts never fire while typing, and arrow keys stay with the base switch, the Steps/Parts tabs, the palette and the Steps list, which they move through. Drag the stage to pan, pinch or scroll to zoom, tap a tower to peek at its digits. To the cards puts Output's first value on the cards in the equation space, in the machine's base. In base 2 or balanced ternary, tapping a × or ÷ term with whole-number operands in the equation space (`1,024 × 3`, `(5 + 3) × 7`) offers **Watch … in the machine**.
- **Reading along.** The sentence line writes the machine as algebra after each beat (`16 × 7` → `16 × 4 + 16 × 3` → … → `112`), the caption says what the beat did, and Steps lists every caption (tap one to replay it). Read along waits after each beat until its caption can be read. The stage is drawn for the eye; Parts is the same machine as a keyboard tree, and a polite live region announces each beat when stepping, or each finished block and the Output while AUTO runs. Under reduced motion (the system setting, or the Reduced motion box, remembered once ticked) each beat crossfades, the camera cuts, beats last 1.5 s and Read along is on. Runs over 400 beats ask first: play at 4× (that run only; the chosen beat length stays) or show the answer. Domain errors (a zero divisor, even a computed one, ln of a non-positive number, a negative shift count) are caught before the run: the block is outlined, the status names the cause and Output shows `[—]`. Runs too large to animate show the exact answer (so does a ×eᵏ count past −6..12); a shift or a power past anything a tower could hold is refused with its reason.
- **Phones and tablets.** On touch the stage takes focus (no keyboard rises) and Run is the big button. In portrait the palette is a strip under the stage, which folds away during a run; Steps and Parts open in a sheet. In landscape the palette and controls form a right rail. The camera keeps every moving bulb at least 18 px across and pans along towers too tall to fit.
- **URLs.** `?machine` opens it; `?machine=empty` opens an empty triangle; `?machine=mul&input=16,7`, `?machine=45/6`, `?machine=(5+3)*7` (a `+` is a plus here, not a space), `&mbase=binary|ternary|e`, `&sp=0.25`, `&pace=together|level` and `&auto=0|1` preload it. `abacus://open/machine` opens it in the apps. With `&automation`, `window.__machine.load()` takes the same names (`{mbase: 'e', machine: 'measure', input: '3'}`).

**Legibility.** The fingerprints, the base trays and the cyber style were read back by TypeSafe's Jev model from pictures the app drew, choosing the true reading among near misses (fingerprints 94–97%, trays 100% after a contrast fix it prompted); see [docs/legibility.md](docs/legibility.md) and `tools/jev-legibility.mjs`. The app itself makes no network requests.

**Number bases.** View ▸ Numerals (or the base button beside the status line, which steps through them) draws the cards in another base. Values stay exact; only the place values change.
- *Base 2*: each tray holds one bit, an LED bulb that is lit or dark, with its place value (2⁰, 2¹, …) in the corner and its digit beneath. Places are grouped in fours. Combining plays the carries bulb by bulb: two lit bulbs in a place merge and the light moves one tray left (`13 + 9 = 10110₂`).
- *Balanced ternary*: each tray holds one trit, a bulb lit blue (1), dark (0) or lit red (−1, written T in text and as a barred 1 under the bulb), so a number needs no minus sign (`−5 = T11`, drawn as `+ T11`). Two like bulbs make a zero pair appear beside them (a blue and a red), and three like bulbs light the next place: 2 = 3 − 1 = 1T.
- *Base e*: the greedy expansion, digits 0, 1 and 2. A stack of place k holds e^k cards, ⌊e^k⌋ whole and the last one sliced to the fractional part. e is transcendental, so only 0, 1 and 2 end; every other number is shown to three places after the point and closes with an ellipsis (`30 = 1102.11…ₑ`). Cards cross-fade rather than carry.

Fractions that do not end in the base (a third in base 2) are drawn as numerator over denominator in that base. × and ÷ cross-fade outside decimal. A long press shows a number's places in the base, each with what one of its cards is worth. Equations can be typed with `0b1011` and `0t1T0` literals. Lessons always count in tens: a lesson switches the cards to decimal and gives the base back when it closes. `?base=binary|ternary|e` opens in a base. The arithmetic is in `src/mvc/bases.js`; `units.js` regroups cards in any whole-number base.

**Style.** View ▸ Style switches every view (equation space, dock, tutor, graph, dialogs and peeks) between the original **school sketchpad** (paper textures, ink, Garamond) and **cyber**, a minimalist future-punk look: neon hairlines on near-black glass, monospace numerals and HUD corner brackets. Colours keep their meaning in both: cyan/blue is positive, magenta/red negative, acid green/green is x, amber a hint. The choice is remembered on the device; `?style=cyber` or `?style=sketchpad` overrides it. Card faces, stack bitmaps and graph cards take their colours from `src/mvc/theme.js`; everything else is in `src/mvc/cyber.css`.

**View** offers horizontal, vertical and automatic layouts, front/depth/spread stack cameras, and zoom. Animations can be paused, scrubbed and finished; undo/redo restore exact states.

**Carrying and borrowing.** A tray has nine cells. Cards arriving at a full tray wait on its rim; when ten gather they stack into one card in their own tray, then the stack slides one tray to the left. A borrow plays the same motion backwards: a card slides one tray to the right and fans out into ten.

## Android and iOS apps

The phone and tablet apps are [Capacitor 8](https://capacitorjs.com) shells (`android/`, `ios/`) around the same code, with app ID `com.metavirtuoso.abacus`. `npm run app:build` writes `dist-app` (0.6 MB: the equation app without the Flash comparison runtime or test bench, plus the vendored `@capacitor/core` module) and copies it into both projects. The apps work fully offline, ask for no permissions beyond vibration, and collect nothing (`public/privacy.html`, linked from View).

```sh
npm ci
npm run android:debug        # android/app/build/outputs/apk/debug/app-debug.apk
npm run android:release      # signed AAB and APK, with the upload key below
npm run icons                # app icons, splash screens and store graphics from the app's own cards
```

- **Android** needs JDK 21 and the Android SDK (API 36, the Play target since August 2026); set `JAVA_HOME` and `ANDROID_HOME`. Release builds are signed with the upload key named in `android/keystore.properties` or `~/.android-keys/abacus-upload.properties` (never committed), or in `ANDROID_KEYSTORE_FILE`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` and `ANDROID_KEY_PASSWORD`. The version (`android/variables.gradle`, `appVersion`) sets the version code: 1.2.3 is 10203.
- **iOS and iPadOS** need Xcode on a Mac: `npx cap open ios`. CI (`.github/workflows/ios.yml`) builds for the simulator on a macOS runner and runs the app on an iPhone and an iPad simulator, keeping screenshots. App Store and TestFlight builds need an Apple Developer Program membership for signing.
- **Layouts.** Phones in portrait get a 3 × 3 dock with 44 px keys; phones in landscape put the dock beside the equation space; tablets get full-size keys. Every touch-screen button is at least 38 px tall, safe areas (notches, home indicators, Android edge-to-edge) are respected, and the graph refits when the device rotates.
- **Haptics** (Capacitor Haptics; the Vibration API on the web): a tick when a card snaps to a partner or the graph point settles in a detent, a heavy bump when a card pops through the mirror or the point lands on an axis, a light pop for each zero pair as it cancels, and a success pattern when a lesson problem is solved.
- **Firm press (3D Touch) and long press.** Pressing a card firmly (3D Touch on iPhone 6s–XS, Apple Pencil, Android screens that report pressure) or holding it still for half a second opens a peek: a number's places as stacks of cards, or every order-of-operations step of a term still to be worked out. Releasing closes it without tapping; moving turns it into a drag. Apple removed 3D Touch hardware from iPhones from the XR and 11 onwards and iPads never had it, so long press is the path most devices use.
- **Quick actions and shortcuts.** A firm press or long press on the home-screen icon offers Lessons, Graph, Numbers and Equation (iOS `UIApplicationShortcutItems`, Android `res/xml/shortcuts.xml`). They open `abacus://open/<place>`, which `src/native.js` routes. Android's back button closes a dialog, the tutor, graph, Numbers or Machine mode before it leaves the app.

## Tutorial videos

`npm run videos` records three narrated tutorials from the real app in headless Chrome: `base-ten` (why ten cards make one), `carry-borrow` (adding and subtracting) and `solving-for-x` (moving pieces across the mirror until the green X is alone). Each is written in landscape 1920×1080 and portrait 1080×1920 to `videos/<name>-<format>.mp4`, with burned-in captions and a matching `.srt`.

```sh
npm run videos                                   # all three, both formats
npm run videos -- base-ten --format portrait     # one video, one format
npm run videos -- carry-borrow --draft           # quick 1× render for review
```

- The page runs on virtual time (`tools/video/page.js`): each video frame advances the app clock exactly, so drags, animations and narration line up frame for frame, and regrouping plays in slow motion while it is described.
- Touches are real DevTools touch events; an overlay draws the fingertip, press ripples, captions, title cards and place-value labels.
- Narration uses ElevenLabs (`tools/video/voice.mjs`) with the voice named by `ELEVENLABS_VOICE` (default `JohnV4`). The key comes from `ELEVENLABS_API_KEY` or the file in `ELEVENLABS_KEY_FILE` (default `~/Desktop/eleven-key.txt`). Lines are cached by content in the Git-ignored `.cache/voice`, so re-rendering costs nothing; only edited lines are synthesized again.
- Scripts live in `tools/video/tutorials.mjs`. Card positions are read live, so one script serves both formats. Requires Chrome and ffmpeg.

## Architecture and mathematics

- `src/engine.js`: exact reduced rationals (BigInt intermediates), the parser, operation terms (`expr` chains with the sign on the first operand; operands may be parenthesised groups or powers), `evaluateStep` in the order of operations, and solution classification.
- `src/mvc/model.js`: immutable equations and validated commands (move, reorder, combine, evaluate, operate, simplify) with undo/redo. Every command is checked to preserve the equation residual (or apply its explicit nonzero factor). `nextStep` is the planner: parentheses, then exponents, then products, zero pairs before same-sign pairs (left to right in the order-of-operations lessons), x gathered where its coefficient stays positive, then scaled to one x.
- `src/mvc/controller.js`: commands, animation lifecycle, drop interpretation; emits `commit` events.
- `src/mvc/view.js`: SVG projection of model state and deterministic transition frames; it cannot change mathematical state. `surface.js` keeps a persistent SVG so textures stay decoded and frames replace only the scene body; `raster.js` rasterizes each 1/10/100-card stack once (the vector drawing remains the reference and fallback).
- `src/mvc/units.js`: signed singleton ledger for addition, subtraction and repeated addition, scheduled on one timeline. Transfers, carries, borrows and cancellations conserve exact weight, and pairs cancel in reading order.
- `src/mvc/operations.js` and `operation-view.js`: card plans and frames for multiplication (copies over a line of cards) and long division (dealing, unstacking, slicing).
- `src/mvc/physics.js` and `drag.js`: drag physics (spring, membrane, magnets, reflow, balance tilt) and the DOM glue that writes transforms each frame.
- `src/mvc/tutor.js`: lessons, problem generators, narration and feedback. `app.js` wires input, dialogs and the tutor bar.
- `src/graph/polynomial.js`: exact polynomial parsing in x and y, roots (rational root theorem, then bracketed numeric roots), intersections, Riemann sums and exact integrals. `intercepts.js` writes out the substitution at an axis crossing. `graph-view.js` renders deterministic SVG; `graph-app.js` handles the tracer, detents, pan/zoom, substitution checks and the area sweep.
- `src/haptics.js`: haptic feedback through Capacitor's Haptics plugin in the native apps and the Vibration API in browsers.
- `src/machine/` (the Machine, loaded on first use): exact BigInt digits and both division conventions (`bigmath.js`), a base registry (`registry.js`, `bt-base.js`; base e in `e-exact.js`, `e-base.js`, loaded on first use of base e), machine trees and parsing (`tree.js`), pure plans of beats as scene diffs (`builder.js`, `plan.js`, `ops/`), a normative layout and camera (`layout.js`), a pure SVG renderer (`render.js`), the beat clock (`clock.js`: AUTO, speed, read along, the Enter rule) and the mode itself (`machine-app.js`: building, keys, camera override, outline, Steps, live region, haptics, `&automation` and `&recording` hooks).

Supported scope: one-variable linear equations and expressions in x, with parentheses/distribution, fractions, decimals, variables on both sides, identities and contradictions. Rational components must fit safe integers; overflow is rejected, as are nonlinear terms, variable denominators and multiplying or dividing both sides by zero. This is not a universal computer algebra system. The original JPEG textures are reused; typography and animation paths are reconstructions, not SWF playback. Solved variable trays show up to nine green units; larger answers remain fully represented on the constant side.

## Tests and regression infrastructure

- `npm test`: exact arithmetic, parser and operation chains, planner termination and residual preservation, 150 random products and every division plan checked for conservation, drag physics (membrane, hysteresis, snapping, reflow), 200 generated problems per tutor lesson (graph lessons: an exact goal point each), polynomial parsing, 200 random root sets recovered exactly, systems, strip sums converging to exact integrals, stack geometry, clock behaviour, and SWF provenance, including a full AVM2 decode of the original.
- `npm run test:visual`: 720 deterministic SVG snapshots (24 scenes × 2 layouts × 3 cameras × 5 timestamps) against reviewed hashes; outputs go to `artifacts/visual`. `npm run test:visual:update` records new hashes after visual review.
- `npm run test:browser`: headless Chrome with DevTools pointer and key events. It drags through the mirror onto a like card, releases inside the membrane, drops in open space and in gaps, taps a product, runs Solve through long division, uses the keyboard and the vertical layout, and runs the tutor flow. In graph mode it drags the point into a root's detent, solves a system, runs the area sweep and completes a graph lesson. It also checks p90 frame time while dragging in both modes.
- `npm run perf`: median/p95 frame times for heavy scenes, failing above `FRAME_BUDGET_MS` (34 ms by default). Scenes hold a 16.7 ms median; the heaviest spread-camera products and divisions reach 33 ms at p95. It also plays the Machine's heaviest beats in both styles (the widest ADD of (2³² − 1)², ((3²⁰ − 1)/2)², (2⁶³ − 1) ÷ 3 and the base-e UNFOLD of 600), failing above a 17 ms median (`MACHINE_MEDIAN_MS`) or the p95 budget.
- The Machine: `node --test` also proves its arithmetic over ranges, every plan's invariants at every beat, the golden traces, the layout and the renderer's beat-boundary property; `npm run test:visual:machine` hashes its scenes in both styles and orientations; `npm run test:browser` adds its 13 browser checks (the Enter ritual, AUTO off, shortcuts in fields, bases, building by tap and drag, phones, the header at 360 px, reduced motion, styles, close paths, domain errors, Watch in the machine, the outline's tab order) and three more from its review (URL and hook presets, arrow keys in the radios and tabs, long runs at 4×); `ONLY=machine` runs just those. `MACHINE_FULL_SQUARE=1 node --test tests/machine-crossengine.test.js` checks the whole |a|, |b| ≤ 200 cross-engine square (321 602 pairs) instead of its default lattice.
- The test bench (`tests.html`) scrubs any scene, layout, camera and frame, runs geometry assertions and compares local pixel baselines. Pixel baselines are Git-ignored and recorded per machine.

CI runs unit, snapshot, browser and frame-time checks (the last two with a 50 ms budget for shared runners) and builds `dist`; `android.yml` builds and lints the Android app, and `ios.yml` builds the iOS app and runs it in iPhone and iPad simulators. ## The original SWF

`public/ABACUS.swf` is the untouched original and `reference.html` plays it through self-hosted Ruffle. `npm run swf:disasm -- absrc::Multiplication` prints the original AVM2 bytecode for any class or method (`--list` names them all). `docs/original-reference.md` records what the original does and does not implement.

## Decimal and original input/display conventions

Known numbers are blue (positive) or red (negative), coefficients included; only the unknown x's tray is green, and a dot between a coefficient and x marks the multiplication. Decimal input keeps decimal notation and entered trailing zeros; explicit slash fractions stay fractions; values are exact reduced rationals either way. Terminating decimals use scaled integer units for carry and borrow.

Whole-number group commas are triangles; the decimal boundary uses the original triangle and dotted mark. Following the SWF's magnitude reset, a group comma follows tenths and hundredths (before thousandths) and repeats before millionths. A decimal unit's textured inner area shrinks by ten for each smaller place. Faces carry k, M, B (and higher) inscriptions with progressively thicker nested outlines. Tray fill is 16% opaque, so a stack passing behind an adjacent tray stays visible.

## Double-click on Windows

Double-click **Start Abacus.cmd**. It starts a local server and opens your default browser; repeated launches reuse that server. Double-click **Stop Abacus.cmd** to stop it. It finds an existing Node runtime or a standard Node.js installation. Temporary state and logs stay in the Git-ignored `.runtime` directory.

## Run on Ubuntu

Double-click **Start Abacus.desktop**, or run `./Start\ Abacus.sh`. Repeated launches reuse the server; `./Stop\ Abacus.sh` stops it. Node.js 20 or newer is required.
